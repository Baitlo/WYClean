# 文本清洗规则对照表

本文档用于把“原项目”的文本清洗规则映射到本项目的实现，便于后续在代码层做单元测试与行为对齐。

## 规则对照总览

| 原项目规则点 | 本项目对应实现方法名 | 差异说明 |
| --- | --- | --- |
| 修正中英文标点（全角/半角互转） | `normalizePunctuation()` | 本项目默认**保留中文语境**：中文句子优先输出中文标点（`，。！？；：`），而不是统一替换成英文标点。 |
| 折叠多余空白字符（空格、Tab、换行） | `normalizeWhitespace()` | 原项目倾向“压到单空格”；本项目采用**按语义保留换行**策略：段落换行保留，行内多空白压缩为 1 个空格。 |
| 清理首尾空白与零宽字符 | `trimAndRemoveZeroWidth()` | 本项目额外清理 `\u200B-\u200D`、`\uFEFF`，避免中文输入法或复制来源导致的隐形字符残留。 |
| 中英文之间自动补空格 | `insertCjkLatinSpacing()` | 本项目只在 **CJK 与 ASCII 字母/数字相邻**时补空格；对 URL、邮箱、版本号等模式不插空格，避免破坏 token。 |
| 统一省略号与破折号写法 | `normalizeEllipsisAndDash()` | 原项目可能统一为 `...` / `--`；本项目中文语境优先 `……` 与 `——`，英文语境保留 `...` 与 `—`。 |
| 清理重复标点（如 `！！！！！`） | `collapseRepeatedPunctuation()` | 本项目按标点类别设置上限：语气标点（`! ?`）最多 2 个，句末标点（`。.`）最多 1 个。 |
| 标准化引号与括号配对 | `normalizeQuotesAndBrackets()` | 原项目可能只做字符替换；本项目增加轻量配对修复（可修正明显错配），但不会做复杂语法级重排。 |

> 注：上述方法名为本项目文档约定名，用于测试与实现对齐；若后续代码命名调整，请同步更新本表。

## 参数化测试示例（输入 -> 输出）

以下示例可直接转成参数化测试数据（例如 `[{ input, expected }]`）。

### 1) `normalizePunctuation()`

- `"你好,world!" -> "你好，world！"`
- `"版本更新:修复bug." -> "版本更新：修复bug。"`

### 2) `normalizeWhitespace()`

- `"A   B\t\tC" -> "A B C"`
- `"第一段\n\n\n第二段" -> "第一段\n\n第二段"`

### 3) `trimAndRemoveZeroWidth()`

- `"\u200B 你好世界 \uFEFF" -> "你好世界"`
- `"\t\n 文本 \n" -> "文本"`

### 4) `insertCjkLatinSpacing()`

- `"使用GPT4模型" -> "使用 GPT4 模型"`
- `"请访问https://example.com测试" -> "请访问 https://example.com 测试"`

### 5) `normalizeEllipsisAndDash()`

- `"等等...我想想--马上" -> "等等……我想想——马上"`
- `"well... maybe - no" -> "well... maybe — no"`

### 6) `collapseRepeatedPunctuation()`

- `"真的吗？？？？" -> "真的吗？？"`
- `"完成了。。。。" -> "完成了。"`

### 7) `normalizeQuotesAndBrackets()`

- `"他说:\"你好\"" -> "他说：“你好”"`
- `"函数调用(参数】" -> "函数调用（参数）"`

## 不可直接照搬的部分（迁移注意事项）

以下内容从原项目迁移时**不能机械复制**，必须按本项目运行环境重设：

1. **事件模型差异**
   - 原项目若来自浏览器插件（`keydown/input/composition*` 事件链），其触发时机与批处理边界依赖 DOM 生命周期。
   - 本项目若运行在 macOS 本地（如快捷键触发、剪贴板监听、文本服务回调），事件粒度与节流策略不同。
   - 结论：清洗函数应设计为**纯函数 + 显式调用**，不要耦合浏览器事件顺序假设。

2. **输入法合成态处理差异**
   - 浏览器可通过 `compositionstart/compositionend` 判断中文输入法合成阶段。
   - 本地事件模型可能拿不到完整合成态信号，若在合成中强制清洗会造成光标跳动或候选词被截断。
   - 结论：本项目应优先在“提交文本后”执行清洗，或由调用方保证时机。

3. **选区与光标恢复机制差异**
   - 浏览器环境通常有 `selectionStart/selectionEnd` 等定位能力。
   - 本地富文本控件/跨应用粘贴不一定提供等价 API。
   - 结论：规则实现应与“光标恢复”解耦，必要时输出 diff/offset 建议，由上层决定如何应用。

4. **字符边界与 Unicode 实现差异**
   - JS 正则（原项目）与本项目语言运行时在 Unicode 属性类、lookbehind 支持上可能不同。
   - 结论：涉及 CJK 边界、emoji、变体选择符的规则应补充跨运行时测试用例，避免“同规则不同结果”。
